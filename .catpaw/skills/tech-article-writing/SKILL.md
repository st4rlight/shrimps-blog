# shrimps-blog 技术文章编写

为 shrimps-blog 博客编写高质量技术文章，遵循多轮迭代写作流程。

---

## 1. 判断文章归属

### 1.1 读取导航结构

首先读取 `docs/.vuepress/config.ts` 中的 `navbar` 和 `collections` 配置，确认当前可用的一级栏目与二级分类。

### 1.2 当前栏目与分类速查

> **注意**：以 `config.ts` 实际内容为准，下表可能过时。

| 一级栏目 | 目录 | 二级分类（示例） |
|---------|------|----------------|
| AI客服系统 | `docs/ai-cs/` | 周边生态工具 |
| AI学习 | `docs/ai-study/` | SDD规范驱动开发、Harness Engineering、AI Infra演进、RAG技术学习、AI周边生态 |
| AI源码 | `docs/ai-source/` | ClaudeCode源码分析、DeepAgents源码分析、OpenClaw源码分析 |
| 拾遗补阙 | `docs/notes/` | Java拾遗、离线数仓建设、数据库技术 |
| 思考领悟 | `docs/thoughts/` | 反思感悟 |

### 1.3 归属决策规则

1. **AI客服系统**：客服相关技术栈（Akka、流程引擎、表达式引擎等）
2. **AI学习**：AI 领域学习笔记、方法论、架构演进、RAG 等
3. **AI源码**：对开源 AI 项目/工具的源码深度分析
4. **拾遗补阙**：基础技术补漏（Java、数据库、数仓等）
5. **思考领悟**：非技术或半技术反思类

如果用户未明确指定栏目，根据文章主题自动判断，并向用户确认。

## 2. 文章结构规范

### 2.1 Frontmatter

```yaml
---
title: 文章标题
tags:
  - 标签1
  - 标签2
  - 标签3
excerpt: 一句话摘要，概括文章核心内容。
createTime: YYYY/MM/DD HH:MM:SS
permalink: /栏目名/文章标识名/
---
```

- `permalink` 最后一段即文章 URL 标识名，使用 kebab-case
- `tags` 3~5 个，覆盖技术领域和具体主题
- `excerpt` 控制在一两句话

### 2.2 正文结构模板

```markdown
# 文章标题

> 一段引言，点明文章要解决什么问题、适合什么读者。

[[TOC]]

---

## 背景与动机

（为什么写这篇文章，解决什么问题）

## 核心概念 / 总览

![总览图](/栏目/文章目录名/xxx-overview.svg)

（关键概念定义、整体架构图）

## 主体内容

### 子主题1
（代码示例 + 解释 + 要点表格）

### 子主题2
（对比图 + 对比表格 + 分析）

## 实践建议 / 选型指南

![决策图](/栏目/文章目录名/xxx-guide.svg)

（工程实践建议、选型决策树）

## 总结

（核心要点回顾、进一步阅读建议）
```

### 2.3 内容要素清单

每篇文章应包含以下要素（按文章类型灵活取舍）：

| 要素 | 说明 | 适用场景 |
|------|------|---------|
| 引言 | 用 `>` 引用块，1-3 句话 | 所有文章 |
| 总览图 | overview 类型 SVG | 概念性文章 |
| 代码示例 | 带注释的代码块 | 技术教程类 |
| 对比表格 | Markdown 表格 | 多方案对比类 |
| 对比图 | comparison/vs 类型 SVG | 多方案对比类 |
| 机制原理图 | mechanism 类型 SVG | 原理深入类 |
| 决策图 | guide 类型 SVG | 选型建议类 |
| 权衡图 | tradeoff 类型 SVG | 架构设计类 |
| 要点总结表 | Markdown 表格 | 所有文章 |
| 实践建议 | 带图标的提示 | 所有文章 |

### 2.4 写作风格

- **语言**：中文为主，技术术语保留英文原文（如 `ReentrantLock`、`Actor Model`）
- **代码注释**：用中文注释关键逻辑
- **强调**：用 `**粗体**` 标注关键概念和注意事项
- **Emoji**：章节标题可适度使用 Emoji 增强可读性（如 🔑、📊、🎯），但不滥用
- **数学公式**：使用 `$...$` 行内或 `$$...$$` 块级 LaTeX 语法
- **层级深度**：H2 为主章节，H3 为子章节，一般不超过 H4

## 3. 配图规范

### 3.1 必须遵循的规范

配图生成**必须**严格遵循 `docs/.vuepress/ILLUSTRATION_SPEC.md` 中的全部规范。在生成配图前，先读取该文件。

### 3.2 核心要点速览

- **格式**：SVG，存放在 `docs/.vuepress/public/{栏目}/{文章目录名}/` 下
- **命名**：kebab-case，`{主题}-{类型}.svg`（如 `sync-overview.svg`）
- **画布**：viewBox 宽 700~840，高 300~580
- **字体**：`'Segoe UI', 'PingFang SC', 'Microsoft YaHei', sans-serif`
- **配色**：Tailwind CSS 色板（详见规范文件）
- **引用**：Markdown 中用绝对路径 `![描述](/栏目/文章目录名/文件名.svg)`

### 3.3 配图类型与插入时机

| 图表类型 | 何时需要 | 插入位置 |
|---------|---------|---------|
| overview | 有多方案/多层级的主题 | 章节开头，背景介绍后 |
| comparison | 有反例 vs 正例或方案 A vs B | 对比分析段落前后 |
| mechanism | 涉及内部机制/流程 | 代码示例之前 |
| guide | 有选型决策逻辑 | 实践建议章节开头 |
| tradeoff | 有维度间的权衡关系 | 总结/注意事项部分 |

### 3.4 配图数量

- 短文（< 200 行）：1~2 张
- 中文（200~500 行）：2~4 张
- 长文（> 500 行）：3~6 张

不强制每篇都有所有类型的图，根据内容选择最合适的。

## 4. 多轮迭代写作流程

文章采用**多轮迭代**方式编写，每轮完成后进行 Review，直至质量达标。

### Round 1：骨架与大纲

1. 确认文章归属栏目（参见第 1 节）
2. 生成 Frontmatter（title、tags、excerpt、permalink）
3. 写出 H1 标题、引言、`[[TOC]]`
4. 列出所有 H2/H3 章节标题，每个标题下用 1-2 句话描述该节要写什么
5. 标注每节计划插入的配图类型（用注释 `<!-- plan: overview -->`）

**Review 1**：检查大纲是否逻辑完整、章节是否覆盖主题、归属栏目是否正确。向用户展示大纲并确认方向。

### Round 2：正文填充

1. 逐章节展开内容，每节至少 2-3 段
2. 补充代码示例（带中文注释）
3. 补充对比表格和要点表格
4. 写出总结段落
5. 移除大纲注释，保留配图位置占位（`<!-- TODO: xxx-overview.svg -->`）

**Review 2**：检查内容准确性、代码正确性、逻辑连贯性、是否有遗漏的知识点。记录待修改项。

### Round 3：配图生成

1. 读取 `docs/.vuepress/ILLUSTRATION_SPEC.md`
2. 为每处配图占位生成 SVG 文件，存入 `public/{栏目}/{文章目录名}/`
3. 在文章中用正确的绝对路径引用 SVG
4. 确保每张图符合配色、字号、布局规范

**Review 3**：检查 SVG 是否符合规范、路径是否正确、图片内容是否与正文呼应。

### Round 4+：精修与收尾

1. 根据 Review 3 反馈修正问题
2. 检查 Markdown 格式（空行、代码块语言标注、表格对齐）
3. 检查 frontmatter 完整性
4. 通读全文，润色表达，确保无错别字
5. 确认 permalink 不与已有文章冲突
6. 更新 `docs/changelog/README.md` 时间轴（如果用户需要）

**Review 4**：最终通读检查。如仍有问题，继续下一轮。如质量达标，完成。

### 终止条件

满足以下全部条件时结束迭代：
- [ ] 大纲逻辑完整，章节无遗漏
- [ ] 正文内容准确，代码可运行
- [ ] 配图符合 ILLUSTRATION_SPEC.md 规范
- [ ] Markdown 格式无错误
- [ ] Frontmatter 完整且 permalink 无冲突
- [ ] 无错别字和语法错误

## 5. 文件操作清单

写一篇新文章涉及以下文件操作：

| 操作 | 文件 | 说明 |
|------|------|------|
| 创建 | `docs/{栏目}/{二级目录}/{文章名}.md` | 文章源文件 |
| 创建 | `docs/.vuepress/public/{栏目}/{二级目录}/{文章目录名}/*.svg` | 配图文件 |
| 修改 | `docs/.vuepress/config.ts` | 在对应 sidebar 的 items 中添加文章路径 |
| 修改 | `docs/changelog/README.md` | 时间轴添加新条目（可选） |
| 修改 | `docs/README.md` | 首页最近更新添加条目（可选） |

### config.ts 注册示例

```typescript
// 在对应 collection 的 sidebar items 数组中添加
items: [
  'java-pickup/java-thread-synchronization.md',
  'java-pickup/新文章名.md',  // ← 新增
],
```
