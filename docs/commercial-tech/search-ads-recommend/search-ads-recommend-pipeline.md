# 搜广推系统全链路详解

> 当你打开一个 App，首页瞬间刷出的内容、搜索时排在前面的结果、信息流里恰到好处出现的广告——背后都是同一套"漏斗式"架构在运转：**从亿级候选池中，用层层递进的筛选，在几百毫秒内挑出你最可能点击的几十条**。

本文拆解搜广推系统的四个核心环节——召回、粗排、精排、重排——每个环节的目标是什么、用什么算法、有哪些关键技术点。最后对比搜索、广告、推荐三大场景的差异，帮你建立完整的认知框架。

---

## 一、整体架构概览

搜广推系统的核心架构是一个**级联漏斗**，本质思想是"从多到少、从粗到精"，在效率与效果之间取得平衡。

![搜广推系统级联漏斗架构](/commercial-tech/search-ads-recommend/search-ads-recommend-pipeline/pipeline-overview.svg)

```
全量候选池（亿级）
    │
    ▼  ① 召回（Recall）
候选集（数千~数万）
    │
    ▼  ② 粗排（Pre-Ranking）
候选集（数百~数千）
    │
    ▼  ③ 精排（Ranking）
候选集（数十~数百）
    │
    ▼  ④ 重排（Re-Ranking）
最终展示（十几~几十条）
```

**为什么不能一步到位？** 核心约束是**算力**。精排模型（如 DIN、DeepFM）单次推理可能需要 1~5ms，如果对亿级候选逐一打分，延迟是线上无法承受的。因此采用分层漏斗：每层用"刚好够用"的模型复杂度，把最贵的计算留给最少的候选。

| 环节 | 核心理念 | 候选规模 | 延迟要求 | 典型模型 | 核心目标 |
|------|---------|----------|---------|---------|---------|
| 召回 | **快+广，宁多勿漏** | 亿 → 数千~数万 | < 5ms | 双塔、CF、图召回、序列召回 | 高召回率 |
| 粗排 | **轻量筛选，逼近精排** | 数千~数万 → 数百~数千 | < 10ms | COLD、蒸馏双塔、轻量 DNN | 效率与效果平衡 |
| 精排 | **算力拉满，精准打分** | 数百~数千 → 数十~数百 | 10~50ms | DIN、DeepFM、MMOE、PLE | 精准排序 |
| 重排 | **全局视角，列表优化** | 数十~数百 → 十几~几十条 | < 5ms | DPP、PRM、Seq2Slate | 多样性+策略 |

## 二、召回（Recall）

### 2.1 核心理念与设计哲学

> **召回层的核心矛盾**：亿级候选 vs 毫秒级延迟。
>
> **解决思路**：放弃"逐个打分"，改用"检索式"——先把所有物品变成向量，离线建好 ANN 索引，线上只需要做一次向量近邻搜索。用**空间换时间**，用**多路并行**保证覆盖度。
>
> **一句话**：**快+广，宁多勿漏**。召回不是在排序，而是在"捞"——只要有可能相关就捞进来，排序的事交给后面。

🎯 **目标**：从亿级全量候选池中，快速"捞"出用户可能感兴趣的数千条候选，追求**高召回率**（宁多勿漏）。

⚡ **核心特点**：

- **速度极快**：毫秒级，必须在海量候选中快速筛选
- **模型轻量**：特征简单，计算量小，支持高并发
- **多路并行**：多路召回同时进行，最后合并去重
- **重覆盖**：宁可多召回一些不相关的，也不能漏掉用户真正感兴趣的

### 2.2 常用算法与模型选型

召回层最大的特点是**多路并行**——没有一种召回方法能覆盖所有场景，实际系统会同时运行多路召回，最后合并去重。每一路都有它擅长的"捕获维度"：

| 类别 | 具体模型 | 擅长捕获的维度 | 为什么选它 |
|------|---------|---------------|----------|
| **向量召回（双塔）** | DSSM、YouTube DNN、MIND、ComiRec | 个性化兴趣匹配 | 工业界最主流。用户/物品独立编码 → 离线建 ANN 索引 → 线上毫秒级检索，是**效率最高**的个性化召回方案 |
| **协同过滤** | ItemCF / UserCF / Swing | 相似用户/物品的群体偏好 | 经典且仍广泛使用。不需要特征工程，只依赖交互数据，实现简单、可解释性强 |
| **关键词 / 倒排索引** | BM25、TF-IDF | Query 相关性 | 搜索场景**必选**。基于关键词精准匹配，是搜索召回的基石 |
| **图召回** | GraphSAGE、PinSage、EGES | 高阶结构化关联 | 基于用户-物品交互图做图嵌入，能捕获**多跳关系**（如"买 A 的人也买 B"的二阶、三阶信号） |
| **序列召回** | SASRec、GRU4Rec | 时序偏好演化 | 基于用户行为序列预测下一个兴趣，建模**短期偏好变化**，适合实时兴趣追踪 |
| **标签 / 内容召回** | 标签匹配、内容相似度 | 属性级匹配 | 基于物品属性做匹配，适合**冷启动**（新物品没有交互数据时仍可召回） |
| **热门 / 运营召回** | 热度榜、新品池、运营位 | 兜底覆盖 | 兜底策略，保证覆盖度与运营需求。简单但不可或缺 |

**💡 工业界选型建议**：

- **推荐场景**：向量召回（双塔）为主路 + 协同过滤 + 图召回 + 热门兜底，4~6 路并行
- **搜索场景**：倒排索引为主路 + 语义向量召回 + 热门兜底
- **广告场景**：人群定向召回 + 语义召回 + 竞价候选

### 2.3 关键技术点

**🔑 双塔模型——工业界最主流的向量召回方案**

双塔模型的核心思想是将用户和物品分别通过独立的塔编码为向量，线上只做向量检索。**为什么双塔是召回首选？** 因为它把最耗时的"物品编码"挪到了离线，线上只需要做一次向量内积/余弦相似度检索——这是 O(1) 或 O(logN) 级别的操作。

| 对比维度 | 双塔模型 | 交叉模型（如精排 DIN） |
|---------|---------|---------------------|
| 编码方式 | 用户、物品独立编码 | 用户-物品交叉编码 |
| 线上计算 | 向量内积/余弦 → ANN 检索 | 逐条前向推理 → 打分 |
| 延迟 | < 5ms | 1~5ms/条 |
| 适用候选量 | 数万~数十万 | 数百~数千 |
| 效果上限 | 较低（缺乏交叉特征） | 较高（充分利用交叉信息） |
| 核心优势 | **极致效率** | **极致效果** |

双塔的"代价"是用户塔和物品塔不能交叉——这意味着**无法建模用户-物品的交互特征**（如用户对某类目的偏好与物品类目的匹配），这是召回层为了速度必须接受的牺牲。

1. **离线阶段**：用户塔和物品塔独立编码 → 物品向量离线存入 ANN 索引
2. **在线阶段**：用户实时编码为向量 → 用 ANN（近似最近邻）检索 TopK

```
用户侧                        物品侧
┌──────────┐                ┌──────────┐
│ 用户特征  │                │ 物品特征  │
│ (画像/   │                │ (属性/   │
│  行为序列)│                │  标签)   │
└────┬─────┘                └────┬─────┘
     │                           │
     ▼                           ▼
┌──────────┐                ┌──────────┐
│  用户塔   │                │  物品塔   │
│ (MLP/DNN)│                │ (MLP/DNN)│
└────┬─────┘                └────┬─────┘
     │                           │
     ▼                           ▼
  用户向量 u                   物品向量 v
     │                           │
     └───────── · ───────────────┘
              内积 / 余弦相似度
```

**🔑 负采样策略**

双塔模型训练时，正样本是用户实际交互的物品，负样本需要从全量物品中采样。负采样策略直接影响模型质量：

| 策略 | 说明 | 优缺点 |
|------|------|--------|
| Batch 内负采样 | 同一个 Batch 内其他用户的正样本作为负样本 | 实现简单，但负样本偏热门 |
| 全局随机采样 | 从全量物品中随机采样 | 分布均匀，但可能太简单 |
| 混合采样 | 随机 + 热门 + 硬负例混合 | 效果最好，工业界主流 |
| Hard Negative Mining | 挖掘与正样本相似但不相关的"难例" | 提升模型区分度，但实现复杂 |

**🔑 损失函数**

| 损失函数 | 公式思想 | 适用场景 |
|---------|---------|---------|
| Sampled Softmax Loss | 采样部分负例近似全量 Softmax | 多分类召回，工业界最常用 |
| BPR Loss | 正样本得分 > 负样本得分 | Pairwise 排序，简单高效 |
| Contrastive Loss | 拉近正样本、推远负样本 | 自监督学习、对比学习场景 |

## 三、粗排（Pre-Ranking）

### 3.1 核心理念与设计哲学

> **粗排层的核心矛盾**：召回进来的数千条候选，精排打不动（延迟太高），但又不能直接随机丢弃（会丢失好结果）。
>
> **解决思路**：用一个"便宜但尽量准"的模型快速打分，把明显不相关的过滤掉，让精排只处理"有希望"的候选。关键约束是——**粗排的结果要尽量和精排一致**，否则粗排丢弃的恰好是精排想要保留的，效果就崩了。
>
> **一句话**：**轻量筛选，逼近精排**。粗排不是在做最终排序，而是在"替精排先筛一轮"，所以它最核心的技术是**知识蒸馏**——让粗排学会精排的判断力。

🎯 **目标**：对召回的数千条候选做初步筛选，缩减到数百~千条，**减轻精排压力**。是效率与效果的平衡点。

⚡ **核心特点**：

- **模型比召回复杂**，但比精排轻量
- **延迟要求严格**（通常 < 10ms），需要在有限算力内筛选
- **可用特征比召回多**，但比精排少（部分实时特征可能来不及获取）
- **评估重点**：与精排的排序一致性、对精排 Top 结果的保留率

### 3.2 模型演进与选型

粗排模型经历了从简单到复杂的演进，核心驱动力是**在有限延迟内尽可能逼近精排效果**：

| 演进阶段 | 模型 | 核心理念 | 为什么用 | 局限 |
|---------|------|---------|---------|------|
| **向量内积** | 用户向量 · 物品向量 | 复用召回的向量，直接做内积 | 零额外计算，最快 | 效果差，和召回同质 |
| **增强双塔** | SENet 双塔、并联双塔 | 在召回双塔基础上加更多特征 | 比内积好，延迟可控 | 仍缺乏交叉特征 |
| **轻量交叉** | COLD（阿里） | 轻量级特征交叉 + 知识蒸馏 | **工业界粗排标杆**，效果/延迟平衡最好 | 实现复杂 |
| **蒸馏模型** | 精排蒸馏 → 浅层 MLP | 用精排（Teacher）指导粗排（Student） | 几乎所有方案都用蒸馏 | 训练成本高 |

**💡 工业界选型建议**：

- **起步阶段**：增强双塔（SENet 双塔 / 并联双塔），在召回双塔基础上加更多特征，实现简单
- **进阶阶段**：COLD 或类似轻量交叉模型 + 知识蒸馏，效果/延迟平衡最好
- **极致效率**：向量内积模型（适合候选量极大、延迟极度敏感的场景）

### 3.3 关键技术点

**🔑 知识蒸馏——粗排最核心的技术**

知识蒸馏让粗排模型学习精排模型的排序能力，而非简单地拟合点击标签。蒸馏方式主要有三种：

| 蒸馏方式 | 蒸馏内容 | 说明 |
|---------|---------|------|
| **Logit 蒸馏** | 精排输出的概率值（Soft Label） | 学生模型同时拟合真实标签和 Teacher 的输出概率 |
| **特征蒸馏** | 精排中间层特征表示 | 让学生模型的隐藏层逼近 Teacher 的隐藏层 |
| **排序蒸馏** | 精排的排序顺序（Pairwise/Listwise） | 学生模型学习 Teacher 的相对排序关系 |

实际工程中，**Logit 蒸馏**最简单有效，**排序蒸馏**效果最好但训练复杂。

**🔑 样本构造策略**

粗排的训练样本构造与召回不同，**更接近精排**：

- **正样本**：真实曝光且点击的样本
- **负样本**：真实曝光但未点击的样本（而非随机采样）
- 原因：粗排需要学习区分"有点击"和"无点击"的真实分布，而非"相关"和"随机"的分布

**🔑 评估指标**

| 指标 | 说明 |
|------|------|
| NDCG@K 对齐度 | 粗排 TopK 与精排 TopK 的排序一致性 |
| TopK 保留率 | 精排 TopK 结果中，有多少被粗排保留 |
| AUC | 粗排模型自身的分类能力 |

## 四、精排（Ranking）

### 4.1 核心理念与设计哲学

> **精排层的核心矛盾**：前面漏斗已经把候选缩减到数百条，总算力预算够用了——那就在这里**把模型拉满**。
>
> **解决思路**：精排是整个漏斗中**唯一可以"不惜代价"追求效果**的环节。候选量少（数百条），延迟预算多（几十 ms），所以可以用最复杂的模型、最丰富的特征、最多样的目标。精排效果每提升 1%，直接反映到业务指标。
>
> **一句话**：**算力拉满，精准打分**。精排的哲学是"效果至上"——只要在延迟预算内，模型越复杂越好、特征越多越好、目标越全越好。

🎯 **目标**：对数百条候选做**精准打分排序**，是效果最核心的环节，可以使用最复杂的模型和最丰富的特征。

⚡ **核心特点**：

- **模型复杂度高**：深度网络、特征交叉、序列建模等
- **特征丰富**：用户画像、物品属性、上下文、实时行为序列、交叉特征
- **多目标预估**：CTR、CVR、时长、互动等多个目标联合建模
- **延迟容忍度相对较高**：几十 ms（候选量少，可以用更贵的模型）

### 4.2 模型演进路线与选型

精排模型经历了从线性到深度、从单目标到多目标的持续演进，**每一次演进都对应着对"特征利用"或"目标建模"的一次突破**：

![精排模型演进路线](/commercial-tech/search-ads-recommend/search-ads-recommend-pipeline/ranking-model-evolution.svg)

| 阶段 | 模型 | 核心理念 | 解决了什么问题 | 为什么选它 |
|------|------|---------|-------------|----------|
| **经典** | LR | 线性模型 + 人工特征交叉 | 推荐系统的起点 | 简单高效，可解释性强，适合快速上线 |
| **经典** | FM | 隐向量内积自动学二阶交叉 | LR 需要人工构造组合特征 | 自动学习特征组合，省去人工特征工程 |
| **经典** | FFM | 不同 Field 使用不同隐向量 | FM 对所有特征对用同一个隐向量 | 细粒度交叉，效果更好但参数更多 |
| **深度** | Wide&Deep | 宽记忆 + 深泛化 | 单靠 DNN 泛化能力不够，单靠线性记忆能力不足 | 联合训练，同时学习记忆规则和泛化模式 |
| **深度** | DeepFM | FM + DNN 共享 Embedding | Wide&Deep 的 Wide 部分仍需人工特征工程 | FM 自动交叉 + DNN 深层交叉，无需人工 |
| **深度** | DCN / DCN-v2 | 显式交叉网络 + DNN | DNN 的隐式交叉效率低 | 结构化显式交叉，用更少参数达到更好交叉效果 |
| **注意力** | DIN | Target Attention 建模行为序列 | 传统方法对行为序列做 Pooling，丢失重点 | 不同目标物品对行为的注意力不同，精准提取兴趣 |
| **注意力** | DIEN | 兴趣演化 + GRU | DIN 忽略了兴趣的动态变化 | 捕获兴趣随时间的演化轨迹 |
| **注意力** | DSIN | 按会话切分行为序列 | 行为序列内存在兴趣切换 | 按会话分组建模，更符合真实浏览行为 |
| **多目标** | MMOE | 多门控混合专家 | Hard-sharing 导致负迁移 | 不同任务通过门控选择不同的专家组合 |
| **多目标** | PLE | 任务专属专家 + 共享专家 | MMOE 仍有任务干扰 | 显式区分共享/独享专家，更好地解决负迁移 |
| **多目标** | ESMM | CVR = CTR × CTCVR | CVR 样本稀疏且存在选择偏差 | 利用全量曝光样本，间接学习 CVR |
| **前沿** | RankMixer | 特征 Token 化 + MLP-Mixer | 推荐领域是否存在 Scaling Law | 仿 NLP 的 Token 化思路，验证模型越大效果越好 |
| **前沿** | Hiformer | 层次化信息融合 Transformer | 长序列和短序列的联合建模 | 分层处理长短序列，平衡效果与效率 |
| **前沿** | GDCN | 门控深度交叉网络 | 传统交叉网络对所有特征一视同仁 | 动态门控选择重要特征再交叉 |

**💡 工业界精排选型建议**：

| 场景 | 推荐模型组合 | 理由 |
|------|------------|------|
| **推荐（CTR+时长+互动）** | DeepFM/DCN-v2 + DIN + PLE | 特征交叉 + 序列建模 + 多目标，工业界最经典组合 |
| **搜索（相关性+CTR）** | DCN-v2 + DIEN + 双塔语义 | 显式交叉 + 兴趣演化 + 语义理解，平衡相关性与个性化 |
| **广告（CTR+CVR+出价）** | DeepFM + MMOE/PLE + ESMM | 多目标联合 + CVR 间接学习，适合广告转化链路长的特点 |

### 4.3 关键技术点

**🔑 特征工程**

精排能使用最丰富的特征，是效果提升的基础：

| 特征类型 | 示例 | 说明 |
|---------|------|------|
| 用户画像 | 年龄、性别、消费等级、兴趣标签 | 离线计算，定期更新 |
| 物品属性 | 类目、品牌、价格、时长、质量分 | 物品自身静态属性 |
| 上下文 | 时间、地域、设备、网络环境 | 实时获取 |
| 实时行为序列 | 最近点击/收藏/购买的物品列表 | 最强信号，需实时获取 |
| 交叉特征 | 用户×类目、Query×标题 | 人工或自动构造的组合特征 |

**🔑 多目标融合**

精排通常不是只预估 CTR，而是多个目标联合预估后加权融合：

$$Score = CTR^{\alpha} \times CVR^{\beta} \times Duration^{\gamma} \times Interaction^{\delta}$$

其中 $\alpha, \beta, \gamma, \delta$ 是各目标的权重，通常通过离线网格搜索或在线 A/B 实验调优。

| 目标 | 含义 | 典型模型 |
|------|------|---------|
| CTR | 点击率 | 所有精排模型 |
| CVR | 转化率 | ESMM、ESM2 |
| Duration | 观看/停留时长 | 多目标 MMOE/PLE |
| Interaction | 互动率（点赞/收藏/分享） | 多目标 MMOE/PLE |

**🔑 序列建模**

用户行为序列是精排中**最关键的特征**，建模方式持续演进：

| 方法 | 核心思想 | 序列长度 | 计算方式 |
|------|---------|---------|---------|
| DIN | Target Attention | ~50 | 目标物品作为 Query |
| DIEN | 兴趣演化 + GRU | ~50 | 提取兴趣 → 演化 |
| SIM | 长序列检索 | ~1000 | 先检索后建模 |
| ETA | 高效长序列 | ~1000 | End-to-End Target Attention |
| TWIN | 时间感知长序列 | ~1000 | 时间衰减 + Target Attention |

**🔑 2025-2026 前沿趋势**

将特征和序列 **Token 化**，用多层 Transformer / MLP-Mixer 建模，验证推荐领域的 **Scaling Law**：

- **核心假设**：模型参数量增大 → 效果持续提升（类似 NLP 领域的经验）
- **关键挑战**：推荐数据的稀疏性、在线延迟约束
- **代表工作**：字节跳动 RankMixer、阿里 FinalMLP

## 五、重排（Re-Ranking）

### 5.1 核心理念与设计哲学

> **重排层的核心矛盾**：精排是"逐条打分"，每个候选独立评估——但用户看到的不是一个分数，而是一个**列表**。连续 5 个同质视频、连续 3 个同品牌广告，精排管不了，用户却很反感。
>
> **解决思路**：从"逐条打分"跃迁到"列表级优化"。重排不再问"这条好不好"，而是问"这组列表整体好不好"——考虑多样性、上下文、业务策略，对精排结果做全局调整。
>
> **一句话**：**全局视角，列表优化**。重排不是在打分，而是在"排兵布阵"——第 1 条放什么、第 2 条放什么、广告插在第几位，都是全局最优问题。

🎯 **目标**：在精排结果基础上，做**全局优化和策略调整**，解决精排逐条打分无法处理的列表级问题。

⚡ **核心特点**：

- 考虑候选之间的**相互关系**（多样性、上下文）
- 融入**业务策略和约束**
- 不改变核心相关性，**调整展示顺序**
- 本质是从"逐条打分"到"列表级优化"的跃迁

### 5.2 模型演进与选型

重排模型经历了从规则驱动到学习驱动的演进，核心驱动力是**从"局部贪心"到"全局最优"**：

| 演进阶段 | 方法 | 核心理念 | 为什么用 | 局限 |
|---------|------|---------|---------|------|
| **规则打散** | 类目/品牌/作者打散 | 简单约束保证基本多样性 | **工业界标配**，实现简单，线上零延迟 | 缺乏个性化，无法学习最优排列 |
| **数学模型** | DPP、MMR | 用概率/优化模型保证多样性 | 理论保证多样性，效果比规则好 | 核矩阵构造复杂，MMR 贪心非全局最优 |
| **列表学习** | PRM、SetRank、DLCM | 对整个列表建模，端到端学习排列 | 考虑上下文，效果最好 | 训练推理成本高，需要列表级标注 |
| **序列生成** | Seq2Slate、GRN | 用 RL/序列生成模型决定排列 | 适合广告混排等复杂场景 | RL 训练不稳定，推理延迟高 |

**💡 工业界选型建议**：

- **起步阶段**：规则打散（类目/品牌/作者打散）+ 业务策略（频控、运营位），简单高效覆盖 80% 场景
- **进阶阶段**：DPP / MMR + 规则打散，数学保证多样性
- **高阶阶段**：Listwise 模型（PRM / SetRank）+ DPP，端到端学习最优排列
- **广告场景**：Seq2Slate / GRN + 竞价排序 + 用户体验约束

### 5.3 关键技术点

**🔑 多样性 vs 精准性的平衡**

精排按得分排序的结果，往往存在**同质化**问题——连续展示 5 个相似的视频或商品，用户体验很差。重排的核心挑战就是在精准性和多样性之间找到平衡。

| 策略 | 思路 | 优缺点 |
|------|------|--------|
| MMR | 每次选择与已选集合"边际相关度最高"的候选 | 效果好但计算量随候选数增长 |
| DPP | 基于子矩阵行列式最大化，数学保证多样性 | 理论优雅，但核矩阵构造复杂 |
| 规则打散 | 按类目/品牌/作者约束间隔 | 简单高效，工业界最常用 |
| Listwise 模型 | 端到端学习最优列表排列 | 效果最好但训练推理成本高 |

**🔑 上下文感知**

重排的关键洞察是：**第 3 个位置放什么取决于前 2 个放了什么**。

- 精排是"逐条打分"，每个候选独立，不考虑它周围的上下文
- 重排是"列表级优化"，候选之间会相互影响

例如：用户刚看完一个搞笑视频，下一个放同样搞笑的视频可能产生疲劳，放一个知识类视频反而更好。

**🔑 广告与自然结果混排**

在商业化场景中，重排还需要处理**广告与自然结果的混排**问题：

| 维度 | 说明 |
|------|------|
| 竞价排序 | 广告按 $eCPM = pCTR \times pCVR \times Bid$ 排序 |
| 用户体验约束 | 不能连续展示广告，需要控制广告密度 |
| 保量约束 | 广告主有保量合约，需保证展示量 |
| 流量分配 | 不同广告位的流量如何分配给不同广告主 |

## 六、搜索 vs 广告 vs 推荐

搜索、广告、推荐虽然共享级联漏斗架构，但在用户意图、排序目标、特殊环节上有显著差异：

![搜索vs广告vs推荐对比](/commercial-tech/search-ads-recommend/search-ads-recommend-pipeline/search-ads-recommend-comparison.svg)

| 维度 | 搜索 | 广告 | 推荐 |
|------|------|------|------|
| **用户意图** | 明确（有 Query） | 半明确（有倾向但非主动搜索） | 模糊（被动消费） |
| **召回核心** | 倒排索引 + 语义匹配 | 定向（人群包）+ 竞价 | 兴趣召回为主 |
| **排序目标** | 相关性 + 质量 | $eCPM = pCTR \times pCVR \times Bid$ | 多目标（CTR / 时长 / 互动） |
| **特殊环节** | Query 理解、意图识别 | 竞价机制、预算控制、ROI 约束 | 兴趣探索、冷启动 |
| **评估核心** | NDCG / MRR（相关性导向） | ROI / GMV（商业导向） | CTR / 时长 / 留存（体验导向） |
| **反馈速度** | 即时（用户点击即反馈） | 延迟（转化链路长） | 即时（点击/停留） |

### 6.1 搜索的特殊性

搜索的核心是**理解用户意图**，从 Query 到结果需要经过完整的语义理解链路：

- **Query 理解**：分词、纠错、改写、意图识别（导航/信息/交易）
- **语义匹配**：从关键词匹配到语义理解（BERT/ColBERT/DPR）
- **相关性保障**：搜索结果必须与 Query 相关，不能仅靠 CTR 排序

### 6.2 广告的特殊性

广告的核心是**商业价值最大化**，排序不仅看用户兴趣，还看广告主的出价：

- **竞价机制**：GSP（广义第二价格）、VCG 等拍卖机制
- **预算控制**：Pacing、匀速投放，确保广告主预算不超支
- **ROI 约束**：广告主的投入产出比必须达标
- **冷启动**：新广告没有历史数据，需要探索策略

### 6.3 推荐的特殊性

推荐的核心是**挖掘隐式兴趣**，用户没有明确表达需求：

- **兴趣探索**：不能只推用户已知的兴趣，需要适当探索新领域（Explore vs Exploit）
- **冷启动**：新用户没有行为，新物品没有交互，需要特殊策略
- **长期价值**：不能只优化短期点击，要考虑长期留存和满意度

## 七、核心设计哲学

![搜广推系统核心权衡](/commercial-tech/search-ads-recommend/search-ads-recommend-pipeline/pipeline-tradeoff.svg)

搜广推系统所有设计的背后，是同一个核心哲学：

> **算力有限，分层漏斗，每层用"刚好够用"的模型复杂度，把最贵的计算留给最少的候选。**

这个哲学体现在多个维度的权衡：

| 权衡维度 | 一端 | 另一端 | 取舍原则 |
|---------|------|--------|---------|
| 候选量 vs 模型复杂度 | 候选多 → 模型必须轻 | 模型重 → 候选必须少 | 分层漏斗 |
| 召回率 vs 精准率 | 召回层宁多勿漏 | 精排层宁精勿多 | 各层目标不同 |
| 多样性 vs 相关性 | 重排保证体验 | 精排追求精准 | 重排平衡 |
| 实时性 vs 效果 | 实时特征效果好 | 获取延迟高 | 粗排用离线，精排用实时 |
| 探索 vs 利用 | 需要探索新兴趣 | 利用已知兴趣更安全 | 推荐场景尤其重要 |

**一句话总结**：

```
┌─────────────────────────────────────────────────────────┐
│  召回：快 + 广（双塔/CF/倒排/图）  →  数千候选          │
│  粗排：轻量筛选（蒸馏双塔/COLD）   →  数百候选          │
│  精排：精准打分（DIN/MMOE/DCN/Transformer） → 数十候选  │
│  重排：全局优化（DPP/打散/策略）   →  最终展示          │
└─────────────────────────────────────────────────────────┘
```

## 总结

本文拆解了搜广推系统的四个核心环节及其关键技术：

| 环节 | 核心理念 | 核心算法 | 关键技术 |
|------|---------|---------|---------|
| **召回** | **快+广，宁多勿漏**——放弃逐个打分，改用检索式 | 双塔、CF、图召回、序列召回 | ANN 检索、负采样策略、多路并行 |
| **粗排** | **轻量筛选，逼近精排**——替精排先筛一轮 | COLD、蒸馏双塔、轻量 DNN | 知识蒸馏（Logit/特征/排序）、样本构造 |
| **精排** | **算力拉满，精准打分**——唯一可以不惜代价的环节 | DIN、DeepFM、MMOE、PLE | 多目标融合、序列建模、特征交叉 |
| **重排** | **全局视角，列表优化**——从逐条打分到排兵布阵 | DPP、PRM、Seq2Slate | 多样性平衡、上下文感知、广告混排 |

三大场景的差异：搜索重**相关性**、广告重**商业价值**、推荐重**用户体验**。但底层共享同一套级联漏斗架构，区别在于各层的模型选择、特征使用和目标函数不同。
